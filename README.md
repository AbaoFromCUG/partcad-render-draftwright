# partcad-render-draftwright

A PartCAD package that produces dimensioned engineering drawings as **PDF**,
**SVG** or **DXF** using [Draftwright](https://github.com/pzfreo/draftwright).
Published in the PartCAD index as `//pub/feature/render/draftwright`.

This package contains the adapter and dependency declarations. PartCAD installs
Draftwright into the implementation's Python sandbox; no engine code is vendored.

## Using it

Draw an object from any package:

```sh
pc --no-ansi render -t pdf -e //pub/feature/render/draftwright //your/package:bracket
pc --no-ansi render -t svg -e //pub/feature/render/draftwright //your/package:bracket
pc --no-ansi render -t dxf -e //pub/feature/render/draftwright //your/package:bracket
```

`-e` selects this package's output implementation. The Draft page's **Drawn by**
field selects the same package. The workspace must import the public index as
`pub` to resolve that address.

Alternatively, depend on the adapter directly:

```yaml
dependencies:
  draftwright:
    type: git
    url: https://github.com/partcad/partcad-render-draftwright
    # Pin revision: to a reviewed commit for reproducible dependencies.

render:
  svg: &drawing
    package: //draftwright
    path: render_draftwright.py
  pdf: *drawing
  dxf: *drawing
```

All three implementations belong to `render:`: a dimensioned drawing is a
document about a shape. PartCAD can request it through `pc export` as well,
but the drawing is not an editable solid or sketch.

## Drawing options

Options can be set per package or per object:

```yaml
render:
  pdf:
    title: Mounting Plate
    number: MP-001
    material: AL 6061-T6
    drawn_by: A. Engineer
    company: ACME Corp.
    revision: A
    date: "2026-11-23"
    page: A3
    scale: 2                   # 2:1; omit for automatic scale
    projection: first          # or third
    zones: false
    auto_dims: true
    reproducible: true
```

`tolerance` supplies the part's general tolerance when explicitly configured;
the adapter does not invent one. Other title fields are `approved_by`,
`document_type` and `sheet`. An omitted option keeps the native engine's default.

## Migration from Draftwright 0.4

The adapter now uses **Draftwright 0.6.1**, whose engine is implemented in Rust.
The old `build_drawing()`, `Drawing.export()` and `Drawing.lint()` API was removed.
The adapter uses the supported `Part`, `Drawing.render()` and
`Drawing.problems` API instead. See the upstream
[Python migration guide](https://github.com/pzfreo/draftwright/blob/v0.6.1/docs/python.md#migrating-from-python-0-4).

- Layout, view selection, scale selection and the generated bytes change with
  the new engine. Compare representative drawings before replacing checked-in output.
- PDF is produced natively. ReportLab and SVGLib are no longer requirements.
- The native engine always writes deterministic files. PartCAD's
  `reproducible: true` is supported; `false` does not disable determinism.
- The native engine always draws a frame. An explicit `frame: false` produces
  a warning explaining that it cannot be hidden.
- `detail_view: false` and `assembly: true` are rejected with a specific error.
  Assembly drawing packs need a separate integration with Draftwright's `Pack`
  API. A compound assembly can still be drawn as ordinary geometry with the
  default options.
- Paper sizes use the native engine's supported named sheets, including `A4`
  through `A0`. Custom `WIDTHxHEIGHT` sheets from 0.4 are not supported.
- The sandbox receives BREP geometry, which does not carry AP242 PMI.
  `pmi: report` or `pmi: annotate` therefore warns that the drawing uses geometry
  only. Importing STEP PMI requires an original STEP document and is outside
  this adapter's current request contract.

An engine finding with severity `error` fails the render after the file has
been written for inspection. Other findings are returned as warnings. Additional
SVG/DXF sheets are reported in the output's `files` list for PartCAD's artifact
cache; PDF includes all sheets in one document.

## Requirements and validation

PartCAD 0.8.27 or later is required. The implementation's sandbox uses:

```yaml
pythonVersion: "3.13"
pythonRequirements:
  - draftwright==0.6.1
  - build123d==0.11.1
```

Draftwright's wheel contains the native engine and does not require Rust to be
installed. build123d supplies the adapter's OCCT geometry bridge. PartCAD installs
both requirements into the sandbox; installing Draftwright into the client's
own Python environment does not update that sandbox.

Run the integration tests in an environment containing those requirements,
`pytest` and `ezdxf`:

```sh
python -m pytest -c /dev/null --rootdir . tests -q
```

The tests render a thin board with inclined and vertical bores to all three
formats, check that the files are readable and deterministic, exercise drawing
options and verify explicit failures for unsupported requests.
